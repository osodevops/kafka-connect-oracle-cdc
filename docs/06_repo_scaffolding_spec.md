**Repository:** `osodevops/kafka-connect-oracle-cdc`

## 2. `CLAUDE.md` content

```markdown
# CLAUDE.md: Project context for AI assistants

## What this is

OSO CDC Connector for Oracle Database is OSO's open-source (Apache-2.0) change
data capture source for Apache Kafka Connect. It reads Oracle Database redo
through LogMiner and replaces Confluent's proprietary Oracle CDC Source and
Debezium's Oracle connector for LogMiner users. Maven group `sh.oso`.

Never use "Oracle" in the product name or any domain name (Oracle trademark
guidelines). The repository and plugin artefact names are descriptive
(kafka-connect-oracle-cdc). Say "for Oracle Database" and keep the
non-affiliation notice in README, site footer and Hub listing. Never publish
database benchmark figures (Oracle licence terms).

| Module | Purpose |
|---|---|
| `oracle-cdc-core` | Capture engine, schema registry, FakeLogMiner and FaultyJdbc test-jar |
| `kafka-connect-oracle-cdc` | `sh.oso.connect.oracle.OracleCdcSourceConnector` (plugin ZIP) |
| `oracle-cdc-doctor` | Preflight checker, redo profiler, admin CLI |
| `e2e-tests` | Testcontainers suites against Oracle Database Free; regression corpus; config reference generator |
| `bench` | Workload generator and correctness oracle |
| `tools/migration` | `migrate_from_confluent.py`, `migrate_from_debezium.py`, `takeover_scn.py`, `verify_cutover.py` |
| `website/` | Docusaurus docs site |

## Building and testing

mvn clean verify              # unit, integration and Oracle Free e2e (Docker)
mvn clean verify -DskipE2E    # without Docker
mvn clean package -DskipTests # plugin ZIP in kafka-connect-oracle-cdc/target

## Non-negotiable rules

- No silent data loss. Any unexpected condition stops the task with a typed
  OracleCdcException. Never add a config option that continues past missing redo,
  corruption or decode failure for captured tables.
- Never read redo or archive files directly. LogMiner only.
- Never copy code from Confluent or OpenLogReplicator. Debezium code may only be
  copied with its Apache-2.0 header kept and an entry in NOTICE, and only after
  review.
- Offsets only encode what the framework acknowledged.
- Every data-loss bug gets a regression test before the fix merges.

## Releasing

Conventional commits on main drive release-please. Merging the release PR tags
vX.Y.Z; the release workflow validates the POM version, builds, signs, deploys to
Maven Central and attaches the plugin ZIP and oracle-cdc-doctor image. Never tag by
hand. A release requires the release gate in docs/testing_strategy.md.

## Support and security policy (public)

SUPPORT.md and SECURITY.md are the source of truth for commitments. Client-facing
text must stay consistent with them. Do not claim 24x7 support or features that
are not in a published release.

## Conventions

- Config keys are `cdc.*`, documented only in the generated reference
  (website/docs/reference/configuration), regenerated by e2e-tests.
- Passwords are Connect PASSWORD configs and never logged; row values are never
  logged unless cdc.log.sensitive.data=true.
- House style for client-facing text: UK English, no em dashes, no emoji, no
  tildes or arrow glyphs in prose, ranges written as words, inline code only for
  genuine identifiers.
- `sales/` is gitignored and never committed.
```

## 3. Build

- Parent POM: Java release 17; Kafka Connect API `provided`; `ojdbc11` compile scope bundled in the plugin ZIP; Maven Enforcer (dependency convergence, banned GPL and AGPL licences via a licence plugin allowlist); Spotless; SpotBugs; JaCoCo with 80 per cent line coverage gate on `oracle-cdc-core`.
- Plugin ZIP follows the Confluent Hub component layout (`manifest.json`, `lib/`, `doc/`, `etc/` with example configs) so it installs with `confluent-hub install` and on MSK Connect and Strimzi image builds.

## 4. CI workflows

| Workflow | Trigger | Jobs |
|---|---|---|
| `ci.yml` | PR and push | Build and T0 on Java 17 and 21; T1 on Oracle Free 23ai; migration tool tests; docs build; upload `migration-evidence` artefact from the Debezium cutover test |
| `nightly.yml` | Schedule | T2 correctness and fault suite on 23ai and 26ai; publish evidence JSON; open an issue on failure |
| `codeql.yml` | PR and weekly | CodeQL for Java and Python |
| `release.yml` | Tag from release-please | Version check, full build, GPG sign, Maven Central deploy, GitHub Release with plugin ZIP, `oracle-cdc-doctor` image push to GHCR with SBOM and provenance |
| `dbz-issue-watch.yml` | Weekly | List new Debezium Oracle issues and open a triage issue (testing strategy section 5) |

19c, 21c, RAC, Data Guard and cloud qualification (T4) run on a self-hosted runner on Sion's workstation (label `cdc-lab-local`) and on the AWS dev RAC host (label `cdc-lab-aws`, started on demand by the workflow); results are attached to the release as a qualification report without database benchmark figures (`07_test_lab_and_budget.md` section 5).

## 6. `CONTRIBUTING.md` clean-room rules

- Contributors must not use Confluent Oracle CDC source, binaries or non-public material, and must not install the Confluent connector on machines used for development.
- Property names and behaviour may be taken only from Confluent's public documentation, cited in `docs/research/`.
- No GPL or AGPL code or dependencies.
- DCO sign-off on every commit.

## 7. `SUPPORT.md` and enterprise support page

Same structure and commitments as the Salesforce repo, adapted:

- Community: GitHub issues and discussions, best effort.
- Enterprise support subscription: support@oso.sh, portal, shared Slack Connect or Teams channel; engineers who write the code answer directly.
- Priorities and targets: P1 within 60 minutes with a workaround or recovery path within four hours; P2 within four hours; P3 one business day; P4 two business days. Business hours 08:00 to 18:00 UK time, Monday to Friday, excluding UK public holidays; no staffed 24x7 desk; out-of-hours cover as a priced option.
- P1 definitions specific to this connector: connector stopped with no workaround; `resume.scn` age approaching archive retention (risk of purge); records suspected lost, duplicated or corrupted; mining causing measurable production impact on the source database.
- Oracle-specific inclusions: `oracle-cdc-doctor` findings review, redo sizing advice, RU and upgrade readiness (each Oracle release update in the supported matrix is tested before customers apply it), DBA script review, migration guidance from Confluent and Debezium.
- Exclusions: operating the Oracle database itself, Oracle licensing questions, GoldenGate and XStream products, Confluent's and Debezium's connectors, Kafka platform operation (available separately).
- Supported versions: current and previous minor release; Oracle versions per the published matrix; Kafka Connect 3.6 and later.
- Statement on Oracle support: "OSO supports the connector. Oracle supports your database. LogMiner is a feature of Oracle Database included in all editions."

## 8. `SECURITY.md`

Identical commitments to the Salesforce repo: private vulnerability reporting through GitHub, acknowledgement within two business days, assessment within five, fixes for critical and high within ten business days, coordinated disclosure.

## 9. Acceptance criteria

- [ ] `mvn clean verify` green on a fresh clone with Docker available.
- [ ] Plugin ZIP installs on Apache Kafka Connect, Strimzi and MSK Connect (smoke test).
- [ ] Licence check fails the build when a GPL dependency is added (tested).
- [ ] release-please produces a release PR from conventional commits; the release workflow publishes to Maven Central staging in a dry run.
- [ ] Docs site builds with the generated configuration reference and no broken links.
