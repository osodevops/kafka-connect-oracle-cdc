# LogMiner operation codes by statement kind

Every `(OPERATION, OPERATION_CODE, ROLLBACK, STATUS)` tuple LogMiner emitted for a scripted workload on a heap table with a CLOB and `ALL COLUMNS` supplemental logging, mined with `DICT_FROM_ONLINE_CATALOG`, `NO_ROWID_IN_STMT` and `NO_SQL_DELIMITER`. Fixes the operation-code list in PRD-00 CORE-MINE-2 and the rollback matching rule in CORE-TX-2. Only rows for the workload tables and the transaction control rows are listed; recursive dictionary SQL from the same session is excluded.

Generated by the `operation-codes` spike in `e2e-tests` against Oracle Database Free and checked on every CI run. Edit by re-running with `-Dreference.update=true`, never by hand.

## Savepoint rollback: how ROLLBACK=1 rows relate to the rows they undo

Scenario: insert 10, savepoint, insert 11, update 10, delete 1, rollback to savepoint, insert 12, commit. Each undo row is matched to the latest earlier row in the transaction with the same ROW_ID; that is the matching rule CORE-TX-2 implements. RS_ID differs between an undo row and its original, so RS_ID cannot be the key.

| Undo row | Undoes | Same RS_ID | Same SSN | SQL_REDO shape |
|---|---|---|---|---|
| DELETE (undo) | UPDATE | no | yes | delete from "<schema>"."T" where ROWID = '...' |
| INSERT (undo) | DELETE | no | yes | insert into "<schema>"."T"("ID","NAME","AMOUNT","NOTE","CREATED") values ('...','...','...',EMPTY_CLOB(),TO_DA... |
| UPDATE (undo) | UPDATE | no | yes | update "<schema>"."T" set "NAME" = '...' |

## Online catalog after DDL (dictionary lag case)

The same DML rows on table LAGCASE mined twice with the online catalog: before any DDL, then after ALTER TABLE ADD and DROP COLUMN on that table. This is the case PRD-03 section 3 step 4 handles with a redo dictionary; ADR-0008 records the decision.

Before the DDL:

| OPERATION | STATUS | SQL_REDO shape | Column names |
|---|---|---|---|
| INSERT | 0 | insert into "<schema>"."LAGCASE"("ID","NAME") values ('...','...') | real column names |
| UPDATE | 0 | update "<schema>"."LAGCASE" set "NAME" = '...' where "ID" = '...' and "NAME" = '...' | real column names |

After the DDL:

| OPERATION | STATUS | SQL_REDO shape | Column names |
|---|---|---|---|
| INSERT | 2 | insert into "<schema>"."LAGCASE"("COL 1","COL 2") values (HEXTORAW(...),HEXTORAW(...)) | generic COL n names |
| UPDATE | 2 | update "<schema>"."LAGCASE" set "COL 2" = HEXTORAW(...) where "COL 1" = HEXTORAW(...) and "COL 2" = HEXTORAW(.... | generic COL n names |
