# LogMiner session behaviours and error codes

Behaviours and ORA codes the engine depends on, observed on Oracle Database Free with the capture user's grants (PRD-00 CORE-ERR classifier, CORE-MINE-7 session reuse, CORE-LOG-4 purge detection, PRD-05 DOC-12).

Generated by the `mining-errors` spike in `e2e-tests` against Oracle Database Free and checked on every CI run. Edit by re-running with `-Dreference.update=true`, never by hand.

## Observed

| Situation | Behaviour |
|---|---|
| ADD_LOGFILE of an archived log removed from disk | ORA-01284: file <file> cannot be opened |
| Mining the CURRENT online redo log | allowed; rows mined from the current online log: some |
| START_LOGMNR again without END_LOGMNR | allowed: a second START_LOGMNR in the same session replaces the range (options are not persistent) |
| START_LOGMNR for an SCN range outside every added log | ORA-01291: missing log file |
| V$ARCHIVED_LOG DELETED/STATUS after RMAN CROSSCHECK and DELETE EXPIRED | RMAN did not run: bash: rman: command not found (the engine treats DELETED = YES or STATUS = D or X as purged, CORE-LOG-4) |
| V$ARCHIVED_LOG DELETED/STATUS for that file afterwards | NO/A (the catalog does not notice an rm; the doctor must check the file, DOC-12) |
| V$PROCESS.PGA_USED_MEM of the mining session | visible |

## Not covered here

- An online log overwritten during a slow fetch (ORA-00310, ORA-00334, ORA-01289) is provoked with FaultyJdbc and a log switch storm in the P1-08 suites, not by this spike.
