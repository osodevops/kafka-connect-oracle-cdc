# Object identifiers across identity-changing DDL

For each DDL, a marker row was inserted before and after it, then mined with the online catalog. Each cell says whether the identifier of the after row equals the before row (`same`) or not (`changed`). This decides how the mining query filters by object and when a mining step must be cut and re-resolved (PRD-00 CORE-MINE-3, ADR-0001).

Generated by the `object-id-stability` spike in `e2e-tests` against Oracle Database Free and checked on every CI run. Edit by re-running with `-Dreference.update=true`, never by hand.

## What DATA_OBJ# and DATA_OBJD# mean

The before-marker row of the first case of each table kind, compared with DBA_OBJECTS identifiers of the table, of the partition the row landed in, and of the IOT top index.

| Table kind | DATA_OBJ# equals | DATA_OBJD# equals | SEG_NAME |
|---|---|---|---|
| heap | table OBJECT_ID | table OBJECT_ID | H |
| iot | IOT top index OBJECT_ID | IOT top index OBJECT_ID | I,SYS_IOT_TOP_<n> |
| partition | partition OBJECT_ID and partition DATA_OBJECT_ID | partition OBJECT_ID and partition DATA_OBJECT_ID | P,P1 |

## Stability matrix

| DDL | DATA_OBJ# | DATA_OBJD# | DATA_OBJV# | DBA_OBJECTS.OBJECT_ID | DBA_OBJECTS.DATA_OBJECT_ID | SEG_NAME after |
|---|---|---|---|---|---|---|
| heap: ALTER TABLE ADD column | same | same | changed | same | same | H |
| heap: ALTER TABLE MOVE | same | changed | same | same | changed | H |
| heap: ALTER TABLE SHRINK SPACE | same | same | same | same | same | H |
| heap: TRUNCATE TABLE | same | changed | same | same | changed | H |
| iot: ALTER TABLE ADD column | same | same | changed | same | changed | I,SYS_IOT_TOP_<n> |
| iot: ALTER TABLE MOVE | same | changed | same | same | same | I,SYS_IOT_TOP_<n> |
| iot: TRUNCATE TABLE | same | changed | same | same | changed | I,SYS_IOT_TOP_<n> |
| partition: ADD PARTITION p4 (marker into new p4) | changed | changed | same | same | same | OBJ# <n> (dropped segment, name unresolvable) |
| partition: ALTER TABLE MOVE PARTITION p1 (marker stays in p1) | same | changed | same | same | changed | P,P1 |
| partition: DROP PARTITION p4 (marker stays in p1) | same | same | same | same | same | P,P1 |
| partition: EXCHANGE PARTITION p3 WITH TABLE x (marker into exchanged p3) | changed | changed | same | same | same | P,P3 |
| partition: MERGE PARTITIONS p2a, p2b (marker into merged p2) | changed | changed | same | same | same | P,P2 |
| partition: SPLIT PARTITION p2 (marker into new p2b) | changed | changed | same | same | same | OBJ# <n> (dropped segment, name unresolvable) |
| partition: TRUNCATE PARTITION p1 (marker stays in p1) | same | changed | same | same | changed | P,P1 |

## Reading the matrix

- DATA_OBJ# is the logical OBJECT_ID of the segment written (the partition for a partitioned table, the top index for an IOT) and survives TRUNCATE, MOVE and partition maintenance of existing partitions. DATA_OBJD# is the physical DATA_OBJECT_ID and changes whenever the segment is rebuilt; it is not used for filtering.
- Rows written into a partition that a DDL created or exchanged (SPLIT, MERGE, ADD, EXCHANGE) carry a new DATA_OBJ#. A server-side `DATA_OBJ# IN (...)` filter resolved before that DDL silently drops them until the list is refreshed, so the step must be cut at such a DDL row and the ids re-resolved (ADR-0001). The same applies to CREATE TABLE for a table matching the include patterns.
- Rows into a segment that was later dropped (SPLIT then MERGE, ADD then DROP) have no SEG_OWNER, SEG_NAME or TABLE_NAME under the online catalog: the id is in the redo, the name is not. Filtering by name would lose them; the id resolved at the time of the DDL keeps them.
- DATA_OBJV# increments on structural DDL (ADD column) and is the hint that the schema version for decoding has changed (PRD-03).
