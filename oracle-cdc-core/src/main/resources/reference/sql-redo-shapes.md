# SQL_REDO literal forms per data type

The literal LogMiner writes into SQL_REDO for every 1.0 data type and the 23ai types (PRD-00 CORE-DEC-1, CORE-DEC-5), one table per type so an unsupported type cannot hide the others, mined with `DICT_FROM_ONLINE_CATALOG`, `NO_ROWID_IN_STMT` and `NO_SQL_DELIMITER`. The third column replaces values by placeholders; the fourth shows the literal with its value under the connector's NLS settings. The raw statements form the parser corpus under `oracle-cdc-core/src/test/resources/sqlredo-corpus/`.

Generated by the `sql-redo-shapes` spike in `e2e-tests` against Oracle Database Free and checked on every CI run. Edit by re-running with `-Dreference.update=true`, never by hand.

## Per type: rows LogMiner emits for an INSERT and the literal form of the value

| Declared type | Rows (OPERATION status) | Literal shape with default NLS | Literal with the connector's NLS settings |
|---|---|---|---|
| BINARY_DOUBLE | INSERT status=0 | '<string>' | '0' |
| BINARY_FLOAT | INSERT status=0 | '<string>' | '1.50000005E+010' |
| BLOB | INSERT status=0, UPDATE status=0 | EMPTY_BLOB() | EMPTY_BLOB() |
| BOOLEAN | UNSUPPORTED status=2 | (no INSERT row) | (no INSERT row) |
| CHAR(10) | INSERT status=0 | '<string>' | 'abc ' |
| CLOB | INSERT status=0, UPDATE status=0 | EMPTY_CLOB() | EMPTY_CLOB() |
| DATE | INSERT status=0 | TO_DATE('<value>', 'DD-MON-RR') | TO_DATE('2026-02-28 13:45:59', 'YYYY-MM-DD HH24:MI:SS') |
| FLOAT | INSERT status=0 | '<string>' | '3.14159' |
| INTERVAL DAY(5) TO SECOND(6) | INSERT status=0 | TO_DSINTERVAL('<value>') | TO_DSINTERVAL('+00005 04:03:02.123456') |
| INTERVAL YEAR(4) TO MONTH | INSERT status=0 | TO_YMINTERVAL('<value>') | TO_YMINTERVAL('+0012-03') |
| JSON | UNSUPPORTED status=2 | (no INSERT row) | (no INSERT row) |
| NCHAR(10) | INSERT status=0 | UNISTR('<value>') | UNISTR('nch\00E1r ') |
| NCLOB | INSERT status=0, UPDATE status=0 | EMPTY_CLOB() | EMPTY_CLOB() |
| NUMBER | INSERT status=0 | '<string>' | '1234567890.123456789' |
| NUMBER(10,2) | INSERT status=0 | '<string>' | '-42.5' |
| NVARCHAR2(100) | INSERT status=0 | UNISTR('<value>') | UNISTR('\00FCn\00EFcode \2603 text') |
| RAW(100) | INSERT status=0 | HEXTORAW('<value>') | HEXTORAW('deadbeef00ff') |
| TIMESTAMP(6) | INSERT status=0 | TO_TIMESTAMP('<value>') | TO_TIMESTAMP('2026-03-29 01:30:00.123456000') |
| TIMESTAMP(6) WITH LOCAL TIME ZONE | INSERT status=0 | TO_TIMESTAMP_TZ('<value>') | TO_TIMESTAMP_TZ('2026-10-25 02:30:00.250000000') |
| TIMESTAMP(6) WITH TIME ZONE | INSERT status=0 | TO_TIMESTAMP_TZ('<value>') | TO_TIMESTAMP_TZ('2026-03-29 01:30:00.500000000 +05:30') |
| TIMESTAMP(9) | INSERT status=0 | TO_TIMESTAMP('<value>') | TO_TIMESTAMP('2026-03-29 01:30:00.123456789') |
| VARCHAR2(100) | INSERT status=0 | '<string>' | 'plain ''quoted'' text' |
| VECTOR(3, FLOAT32) | UNSUPPORTED status=2 | (no INSERT row) | (no INSERT row) |
| XMLTYPE | INSERT status=0, UPDATE status=0, XML DOC BEGIN status=2, XML DOC END status=0, XML DOC WRITE status=2 | (no INSERT row) | (no INSERT row) |

The default session formats (`DD-MON-RR`, no fractional seconds) lose the time of day of a DATE and the precision of a TIMESTAMP, which is why PRD-00 CORE-CONN-4 sets `NLS_DATE_FORMAT`, `NLS_TIMESTAMP_FORMAT`, `NLS_TIMESTAMP_TZ_FORMAT` and `NLS_NUMERIC_CHARACTERS` on every mining session.

## Statement splitting and supplemental logging (combined tables of the classic types)

- Rows with CSF = 1 (statement continues in the next row): observed; longest reassembled statement over 4000 characters: yes.
- UPDATE of two columns with ALL COLUMNS logging, WHERE clause: all 18 columns (key, changed and unchanged).
- UPDATE of two columns with PRIMARY KEY logging only, WHERE clause: 3 columns: key plus the changed columns' old values (PRD-00 CORE-DEC-4 partial before image).
