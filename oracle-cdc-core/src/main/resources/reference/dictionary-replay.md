# Decoding redo written before a DDL

Rows written to a table, then `ALTER TABLE ADD` and `DROP COLUMN` on that table, mined afterwards (a) with the online catalog and (b) with a dictionary stored in the redo logs by `DBMS_LOGMNR_D.BUILD(STORE_IN_REDO_LOGS)` plus `DDL_DICT_TRACKING`. This is the lag-case recovery path of PRD-03 section 3 step 4 and the ADR-0008 gate.

Generated by the `dictionary-replay` spike in `e2e-tests` against Oracle Database Free and checked on every CI run. Edit by re-running with `-Dreference.update=true`, never by hand.

## Decoding per mode

| Mode | OPERATION | STATUS | Column names in SQL_REDO |
|---|---|---|---|
| online catalog | DELETE | 2 | COL 1, COL 2, COL 3 |
| online catalog | INSERT | 2 | COL 1, COL 2, COL 3 |
| online catalog | INSERT | 2 | COL 1, COL 2, COL 3 |
| online catalog | UPDATE | 2 | COL 1, COL 2, COL 3 |
| redo dictionary + DDL tracking | DELETE | 0 | AMOUNT, ID, NAME |
| redo dictionary + DDL tracking | INSERT | 0 | AMOUNT, ID, NAME |
| redo dictionary + DDL tracking | INSERT | 0 | AMOUNT, ID, NAME |
| redo dictionary + DDL tracking | UPDATE | 0 | AMOUNT, ID, NAME |

## Facts

- Dictionary build executed by: the capture user (EXECUTE ON DBMS_LOGMNR_D).
- Archived logs flagged DICTIONARY_BEGIN or DICTIONARY_END around the build: found; a build can span several logs and every one of them must be added to the session.
- Redo-dictionary replay decoded every pre-DDL row with real column names and STATUS 0: yes.
Decision (ADR-0008): the lag case is recoverable when a dictionary build exists in redo before the position; PRD-03 section 3 steps 4 and 5 stand.
